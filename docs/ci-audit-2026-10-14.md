# CI and deployment audit — 2026-10-14

Reviewed all 202 workflow runs created from October 12 through the inspection on October 14. There were 155 successes, 26 failures and 21 cancellations. This is a workflow-run count, not a count of notification emails.

## Confirmed causes and changes

- The reported 5.7.32 run at `165eece` failed because the new browser selector matched both the dialog backdrop and Close button. The selector was corrected before merge. Final PR #132 and merged commit `26184065` passed the regression, Chromium/WebKit and native build gates.
- Five workflow/commit pairs ran for both push and PR events. The audit branch patterns have been removed from both push triggers. All PRs, main pushes and manual dispatches still run the same gates; failures are not ignored or automatically retried.
- The calendar browser journey clicked History immediately after an asynchronous edit/finish save. Failed run 38491527294 records that click while `finishing` was true, so the app correctly blocked it. The journey now waits for the finished Home screen before navigating. Calendar session-count assertions stay unchanged.
- One intermediate source commit failed the stale service-worker cache check. Upload complete, locally validated trees before opening a PR so partial source/generated uploads do not become misleading release candidates.
- Other historical failures included tutorial fixture interference, missed pointer/focus interactions, invalid-backup input-reset waits, local-file draft checks and routine/notification assertions. Their logs were inspected; they are not all classified as harmless. Current browser coverage must continue passing, including the modal readiness fix in 5.7.32, rather than weakening those assertions.
- Pages built the merged 5.7.32 artifact successfully but timed out while `updating_pages`. A single build retry completed successfully. Public `version.json`, `app.js`, `index.html`, `lift-local.html` and `sw.js` matched the merged source byte for byte.

## Publication procedure

Stage source and matching generated files on a fresh branch before opening the PR. Validate the exact final head, recheck the base and head before a SHA-guarded merge, then verify the Pages build and public bytes. A green PR check alone does not prove deployment succeeded. Do not disable checks or change notification preferences to hide actual failures.

This change does not alter app behavior, workout data, backup formats or the 5.7.32 release version.
